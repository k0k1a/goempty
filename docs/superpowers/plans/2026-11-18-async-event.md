# 进程内任务池与事件分发实施计划

**目标：** 按会话中已确认的方案，使用 Ants v2 实现进程内任务池和一对多事件分发。

**约束：** 不操作 Git 状态；不接入真实服务；不提供持久化或自动重试。业务 Payload 类型放在 internal/entity，通用 Event 外壳留在 pkg/event，基础包不导入 internal。保持 HTTP 与定时任务现有行为。

1. `pkg/async`：先测试再实现 New/Start/Submit/Stop、Worker 全忙时原生阻塞并在等待人数超限后拒绝、请求上下文值保留、独立超时、App 取消、panic 日志及关闭等待。
2. `pkg/event`：Event 对象与 Payload、具名处理器注册和 Publish；一个事件占一个 Worker，处理器按注册顺序执行，错误或 panic 不阻断后续处理器。启动时冻结注册，无处理器返回错误。
3. 配置和 App：增加 async 配置，Wire 创建共享 Pool 与 Bus；启动前完成注册，App 启动 Pool 和 Bus，退出时并行停止 HTTP、调度器和 Pool，再清理连接。更新所有构造调用与测试，不手改 Wire 生成文件。
4. 文档及验证：组件 README 记录用法、生命周期、Payload 不可并发修改和提交成功语义；同步业务 Payload 放在 entity、通用外壳留在 pkg/event 的位置约定。运行受影响包测试、race、全量 test/vet/build、差异与格式检查。

**验收：** 同一事件的所有处理器均执行，单个错误/panic 被隔离；并发不超过配置；等待人数超限/关闭/未注册时提交失败；请求结束不取消已接收任务；关闭能唤醒等待者、取消并等待执行中任务，超时返回错误。

**实施细节：** 使用显式 Event{Name, Payload} 识别业务，不引入反射或全局注册表。并发数默认 4，最大阻塞提交者默认 1000，不增加提交等待超时；任务执行超时默认 30 秒。配置变更重启生效。处理器名称在同一事件内唯一。

**统一关闭入口：** 使用公开的 `App.Shutdown(ctx) error` 替代 Close 和私有 shutdown。运行组件并行停止后执行 Wire cleanup；未运行、部分启动失败、外部主动关闭均复用此入口。sync.Once 保存关闭结果，启动与关闭串行协调，关闭后不再启动。Run 脱离运行取消状态提供关闭时间，外部首个 Shutdown 遵循调用方的取消和期限。复用既有生命周期测试，并覆盖未运行关闭、并发启动与关闭、超时结果复用和部分启动失败。
