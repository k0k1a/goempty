# 向已有项目同步模板

以目标项目为主体吸收模板变化，不将目标重新变成模板。创建新项目使用 [goempty-new-project](../goempty-new-project/SKILL.md)。

## 必读规则

- [共享组件目录与边界](../goempty-new-project/references/trimming.md)：公共基线、可选组件、依赖、demo、数据库包装、Kafka 完整包、HTTP + Swagger、测试与文档边界；只维护这一份组件模型，不复制为另一份清单。
- [同步范围与步骤](references/sync.md)：差异分类、内容同步策略、冲突处理与验收。

## 输入与定位

- 源模板由本技能 `.agents/skills/goempty-sync-project/` 所在路径向上定位，核对 AGENTS.md、go.mod、README.md；不以当前工作目录代替源路径，不写死磁盘路径。无法定位时询问。
- 目标为当前工作目录或用户指定的已有项目路径，报告解析后的绝对路径，目标不得是源模板或位于源内。目标不存在时不自行创建，转用创建技能。
- 明确用户要新增的组件、更新的已有能力、指定修复或规范范围。范围不明时只读分析并提出方案，不默认全量同步。
- 读取源与目标适用的 AGENTS.md；结构与模板明显不同时先说明差异，确认适配范围。没有历史模板基线时只能确认当前差异，不能认定目标落后或将目标定制当作错误。

## 同步边界

- 公共基线默认保留，公共能力的更新也须属于确认范围；不因模板存在就恢复目标已裁剪的可选组件，不改目标应用名、module、路由身份或环境凭据。
- 新增组件必须同时接入其现有 demo、配置、装配、生命周期和适用根文档；已有组件的 demo 按确认范围补齐或适配，业务替代实现不直接覆盖，冲突先列方案。
- Kafka 任意一侧引入都同步完整 pkg/kafka 生产代码，但配置、demo 和 App 装配只接入选择的侧。已有同名包逐文件比较合并，不整包覆盖。
- HTTP 与 Swagger 配套；新增 HTTP 同时接入 Swagger。更新已有 HTTP 时若目标没有 Swagger，将补齐内容纳入方案，不静默忽略或未经确认接入。
- 按同步后的数据库组合装配：只有 MySQL 或 PostgreSQL 时直接注入 *gorm.DB，移除包装；两者都有时才用 mysqlHandle/postgresHandle，适配调用方并保留清理。
- 不复制模板测试、测试辅助资源或组件文档；保留目标现有测试与组件文档，不以创建项目的清理规则删除它们。保留并按实际能力增量调整根规范文档及其有效链接。
- 所有写入先有明确方案与授权，不直接覆盖业务或整文件替换骨架；未经单独授权不删除目标文件，不执行改变 Git 状态的操作。

## 工作流程

1. **只读比较**：检查源与目标工作区，读取相关实现和调用方，盘点目标基线、已启用组件、配置、装配、demo、依赖、根文档和已有测试；标记未提交修改与可能冲突，不覆盖用户工作。
2. **提出方案**：将差异分为新增、更新、保持不动、冲突和不在范围；列明生产代码、demo、配置、注入与清理、依赖、生成产物、根文档及现有测试适配，并给出验证方法，按适用门禁取得确认。
3. **增量适配**：按目标命名与结构合并代码和配置，替换源 module 导入但保留目标身份，处理共享 demo 和组件组合；更新根文档，不复制组件文档或模板测试。
4. **生成并验证**：按目标命令重新生成受影响的 Wire、Swagger；依赖变化才 tidy，修改的 Go 文件 gofmt，运行受影响测试、vet 和 build。真实服务只用已确认的隔离环境，不以跳过测试代表通过。
5. **交付差异**：报告新增与更新能力、demo、配置键、根文档、保留的定制、冲突与未处理项、实际验证和未验证项；失败不自动清理或回滚目标文件。
