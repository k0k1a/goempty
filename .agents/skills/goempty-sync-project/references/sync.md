# 同步范围与步骤

共用 [组件目录与边界](../../goempty-new-project/references/trimming.md)，本文件只定义同步策略，不重定义组件清单。以目标项目为主体，不追求与模板完全一致。

## 同步意图与差异分类

- **新增组件**：按用户选择补齐缺失能力及其 demo、配置、装配和根文档，检查依赖闭包；不恢复其他已裁剪组件。
- **更新已有能力**：比较指定组件或公共基线的实现与调用方，适配模板修复和改进；已有实现不是一律不动，也不能整文件覆盖。
- **同步指定修复或规范**：围绕用户指定变化追踪受影响的代码、配置、调用方与文档，不扩展为全量升级。
- 将差异分类为新增、更新、保持不动、冲突、不在范围。目标已有路由、配置键、Service 方法、Wire provider 或业务替代 demo 时，先列出处理建议，不自行并存、改名或覆盖。
- 有明确的源版本和目标派生基线时可据此追踪变化；没有基线只能报告当前差异，不能认定模板一定更新或目标一定错误，不为同步擅自创建持久化清单。

## 按内容同步

| 内容 | 同步方式与边界 |
| --- | --- |
| 公共组件与工具 | 指定范围内新增或更新生产代码；公共分页、通用工具、lo/cast 选型不因暂时无调用而删除。目标旧版本缺失基线时先报告，补齐须纳入方案 |
| demo | 新增组件时必须接入其现有 demo，不能只复制 pkg；已有 demo 按更新范围适配。目标已有同名业务或已改造 demo 时列冲突，确认整合方式，不覆盖业务 |
| 配置 | 同步字段、结构与必要的安全默认值，覆盖目标实际环境文件；保留目标连接参数、凭据及业务配置，不整份复制模板 YAML |
| 装配与生命周期 | 增量修改 provider、Wire、配置绑定、注册、App 参数与启停，适配真实调用方，保留失败清理与退出清理 |
| 依赖与构建 | 只同步本次变更需要的依赖、构建和生成命令；保留目标版本约束，不顺带升级，无引用依赖允许 tidy 移除 |
| 根文档 | 保留并合并 AGENTS.md 阅读入口/约束/验证、architecture.md 目录与职责、conventions.md 选型与规则、README.md 启动与生成命令；CLAUDE.md 只导入 AGENTS.md。只描述基线与实际启用能力，保留目标业务约定 |
| 组件文档 | 不复制 pkg、config、internal、Swagger 等局部使用文档，不删除目标已有文档；必要约定和命令写入适用根文档，不新增指向未复制文档的链接 |
| 测试 | 不复制模板 _test.go、integration-test、测试辅助代码或仅供测试的资源，不新增测试文件；保留目标已有测试，签名或行为变化需要的最小适配纳入方案并验证 |
| 生成产物 | 根据目标源代码和命令重新生成受影响的 Wire、Swagger，不复制模板生成结果或手改 wire_gen.go |
| 排除内容 | 不复制模板技能、模板维护配置、构建产物、日志、缓存、凭据或本机私有配置；不替换目标应用名、module、路由前缀等项目身份 |

## 工作步骤

1. **定位与检查**：由同步技能路径定位源模板，解析目标路径和符号链接，拒绝源本身或源内目标；读取两边适用规范和工作区状态，不覆盖未提交修改。目标结构明显不同时说明并确认是否适配。
2. **盘点与追踪**：检查相关生产实现、调用方、config 字段、各环境 YAML、providers/wire/http/jobs/events/messaging、App、go.mod、生成脚本、demo、根文档和现有测试；区分包代码存在与 App 实际启用，不能用 pkg/kafka 中存在 consumer.go 认定消费者已启用。
3. **提出同步方案**：明确新增与更新范围，列出文件、配置键、demo、注入和清理变化、依赖、根文档、产物生成、测试适配、冲突及未处理项；给出验收与验证方法，按目标门禁确认。已获确认的相同范围不重复询问。
4. **合并生产代码与 demo**：替换源 module 前缀导入，按目标命名和结构增量修改；已有同名文件逐段比较，不整文件覆盖骨架或业务。未经单独授权不删除目标文件。
5. **接入配置与装配**：按同步后的实际组合修改配置、Wire、provider、App、入口与清理；共享 demo 只改必要字段与方法，保护目标已有调用方。不以 nil、空切片、空实现规避装配。
6. **调整根文档**：保留公共基线规则，合并本次同步内容及必要使用说明；不恢复未启用组件的目录或章节，不带入模板测试保留承诺、维护专属规则或失效组件文档链接。按共享文档职责边界，只记录项目开发与使用内容，不写入模板创建、同步、裁剪及内容保留策略。
7. **生成与验证**：按目标 README 运行受影响的 Wire/Swagger 生成，依赖变化才 go mod tidy，修改的 Go 文件 gofmt；先运行受影响的目标已有测试，再按范围运行 vet/build。测试依赖真实服务时先检查隔离条件与副作用，没有环境则跳过并说明。
8. **交付**：列出新增/更新能力与 demo、配置和文档变化、保留的定制、冲突、未处理项、实际验证与未验证内容；不自动回滚或清理目标，不执行未授权 Git 操作。

## 常见组合

- **存储**：补齐连接包、配置、provider、App 注入、Wire 和清理；检查目标 Service/Repo 是否已有同类连接，保持其调用行为。
- **单库与双库**：按共享装配规则，只有 MySQL 或 PostgreSQL 时直接使用 *gorm.DB 并移除包装；新增第二种时将原 provider、newApp、Wire 和调用方改为包装注入的适配纳入方案，保留两个连接的清理。
- **Kafka**：任意一侧新增或同步其底层包时，完整同步 pkg/kafka 的生产代码，排除测试和文档；已有包先比较合并。只新增生产者时，只接入生产配置、发布 demo 和清理，不增加消费者装配；只新增消费者时反之。原本已启用的另一侧保持，不因本次只选一侧就裁掉。
- **HTTP + Swagger**：向无 HTTP 项目接入 server、中间件、响应、路由、Hello 与外部 HTTP demo，同时接入 Swagger 注释、生成工具、产物和生成命令；恢复 PORT 解析与监听，确认取消退出。路由沿用目标项目身份，不直接照搬 /goempty/v1。已有 HTTP 缺 Swagger 时把补齐内容列入确认范围，不单独引入无 HTTP 的 Swagger。
- **调度与事件**：定时任务连带事件总线、异步任务池、HelloJob 和订阅 demo；事件总线连带异步任务池。复用现有装配，不新增空总线或零任务调度器。
- **分页与通用工具**：属于公共基线；明确要求补齐或更新时同步生产代码与规范，不视为可选组件，不新增签名 key 配置或模板测试。

## 验收场景

在获准的隔离副本验证，先准备场景明确的目标，不对真实业务项目做试验：

1. 向仅有 HTTP 的项目新增 MySQL + Redis → 连接装配与清理完整，MySQL 裸 *gorm.DB，无包装；保留原 Handler、测试与业务配置。
2. 向未启用 Kafka 的项目新增消费者 → pkg/kafka 的生产者、消费者等生产代码完整；只新增消费配置、demo 和 App 启停，不新增生产配置、发布 demo 或 POST 发布路由。
3. 向未启用 Kafka 的 HTTP 项目新增生产者 → pkg/kafka 完整，发布 demo、配置、路由与 Swagger 更新；无消费者配置、demo 和 App 装配。
4. 向已有生产者的项目新增消费者 → 比较并合并完整底层包，新增消费 demo 与装配，原生产者和目标定制不丢失。
5. 向无 HTTP 的 worker 接入 HTTP → 同时接入 Swagger、Hello 与外部 HTTP demo，健康端点、路由、取消与清理可用；根文档生成命令有效，无新组件文档或模板测试。
6. 向无 MySQL 的项目新增 PostgreSQL → 裸 *gorm.DB，无 Handle 包装，不恢复 MySQL；向只有 MySQL 的项目新增 PostgreSQL → 经确认使用两种包装，原调用方适配，两个连接清理完整。
7. 新增定时任务 → 同时补齐事件总线、异步任务池、HelloJob 和订阅 demo，不重复装配现有能力。
8. 更新已有组件的指定修复 → 实现与调用方得到适配，不停留于“已有所以不改”；目标定制保留，超范围差异报告，不新增模板测试。
9. 缺少历史基线或存在同名业务冲突 → 先报告差异与处理方案，不判断目标落后，不直接覆盖、改名或删除。
10. 任意同步 → 公共基线保留，不恢复已裁剪能力，不复制模板测试或组件文档，目标已有测试与组件文档保持；根文档与实际能力一致，不含模板操作及内容保留策略，检查生成差异与链接。

上述为执行技能时的验收要求，不代表仅修改技能文本就已实际运行这些场景。
