# 从模板创建新项目

只负责创建新项目，不合并已有目录。向已有项目新增组件或更新模板能力，使用 [goempty-sync-project](../goempty-sync-project/SKILL.md)。

## 保留与裁剪规则

先读两个技能共用的 [组件目录与边界](references/trimming.md)，以源代码核实组件归属与调用关系。

- 公共开发基线默认保留：运行骨架、分页、通用工具、公共业务错误、通用开发规范，以及 lo、cast 等统一选型；不能因暂时无调用就删除。
- 只允许裁剪显式列出的可选组件：HTTP + Swagger、MySQL、PostgreSQL、MongoDB、Redis、Kafka 生产者、Kafka 消费者、定时任务、异步任务池、进程内事件总线。
- 所选组件的实现、demo、配置、装配、生命周期和适用的根文档一起保留；demo 不是独立开关。共享示例按剩余调用关系裁剪，公共基线不按引用裁剪。
- HTTP 与 Swagger 配套保留、配套裁剪；不提供单独的 Swagger 选项。
- Kafka 任意一侧选中，都保留完整 `pkg/kafka` 生产代码；配置、demo 和 App 装配只启用所选侧，两侧都不选才删除整个包。
- MySQL、PostgreSQL 只选一种时，provider 和注入点直接使用 `*gorm.DB`，移除 `mysqlHandle`、`postgresHandle`；两种都选时才保留包装类型，完整保留清理行为。
- 不保留 `_test.go`、`integration-test/`、仅供测试使用的资源和组件文档；保留并按组件选择调整 AGENTS.md、CLAUDE.md、architecture.md、conventions.md 和根 README.md。

## 输入与定位

- 源模板是本技能所在 `.agents/skills/goempty-new-project/` 的项目根目录；根据实际加载路径向上定位，核对 AGENTS.md、go.mod、README.md，不以当前工作目录代替源路径。无法定位时询问模板位置。
- 必需输入为应用名与组件集合。目标默认是源模板父目录下的 `<应用名>`；显式路径优先，相对路径按当前工作目录解析并报告绝对路径。
- Go module 默认等于应用名，显式指定时使用指定值。应用名必须是单个合法目录名且适合配置前缀，不接受路径分隔符、`.`、`..`；不擅自改名。
- 组件集合没有默认值。未指定时列出全部可选组件与依赖，请用户选择；“全部”指公共基线加全部可选组件，“最小”指公共基线加一个运行入口及其 demo。未明确运行入口时询问，不自行决定。
- 至少保留一个运行入口：HTTP、Kafka 消费者或定时任务。事件总线依赖异步任务池；定时任务的现有 demo 依赖事件总线和异步任务池。

## 执行边界

先读源模板及目标位置适用的 AGENTS.md，遵循其确认门禁。已明确对应获确认方案的请求直接实施，不重复确认；组件缺失或新增范围先确认。源模板只读。

创建前解析源、目标绝对路径及已有父目录的符号链接或 junction。目标不得等于源或位于源内；目标已存在时停止，不覆盖或合并。只在新建目标内修改和删除，递归删除前再次检查路径边界，不跟随链接到目标外部。未经单独授权，不执行改变 Git 状态的操作。

## 工作流程

1. **核对源与需求**：检查工作区，只读相关实现、调用方和文档；源有未提交修改时说明采用当前磁盘内容，不清理源。汇总应用名、目标绝对路径、module、公共基线、所选组件及连带依赖、demo、测试与文档排除范围，取得适用授权。
2. **复制所需内容**：复制公共基线、所选组件生产代码、demo、根文档与安全配置样例。排除 `.git`、模板技能与模板维护专属配置、测试、组件文档、构建产物、日志、缓存、凭据及本机私有配置；检查隐藏文件，不一律排除，保留有价值的 .gitignore、.editorconfig 和运行文件，不复制链接指向的源外内容。
3. **调整项目标识**：替换 go.mod module 及原 module 前缀的内部导入，更新应用名、配置文件名、路由前缀中的模板标识与 API 元数据。应用名和 module 分别处理，不全局盲替换；项目文档中的描述按第 5 步文档规则改写，不能仅替换名称。不修改数据库账号或连接真实服务。
4. **按边界裁剪**：同步移除未选组件的专属代码、配置字段、全部环境 YAML 段、Wire 声明、App 参数和启停逻辑、专属依赖及文档条目。保留公共基线和仍需共享的内容，不留 nil、空切片、空实现或占位目录；按组合处理数据库包装与 Kafka 完整包规则。
5. **改写项目文档与规范**：依据应用名、用户已提供的项目用途和实际保留组件，按各自职责改写 AGENTS.md、CLAUDE.md、architecture.md、conventions.md、根 README.md 中涉及项目定位、能力与使用方式的描述，不只替换名称，不再沿用“这是项目模板”“用于创建新服务”等定位；未提供用途时仅中性介绍项目名称、技术栈和已有能力，不虚构业务职责。保留适用的通用规范，按实际能力调整章节、导航和目录树，保留后续开发的测试与验证要求，不声称已有模板测试。组件文档中的必要使用约定与生成命令放入职责对应的根文档，不复制组件文档；删除其失效链接。清除与公共基线规则冲突的“未使用即可裁剪分页或通用工具”等表述。根文档仅描述项目开发与使用，不写入模板创建、同步、裁剪及内容保留策略，这些规则只留在技能中。CLAUDE.md 仅导入 AGENTS.md。
6. **生成与验证**：按目标 README 运行 Wire 生成，不手改 wire_gen.go；保留 HTTP 时生成 Swagger，注释与产物只含实际接口。依赖变化时运行 go mod tidy，不主动升级，不用空白导入强留 lo、cast 等未引用依赖，统一选型规范仍保留。生成失败保留真实错误，不伪造产物。

## 验证与交付

- 对修改的 Go 文件运行 gofmt，运行 `go vet ./...`、`go build ./...`；检查公共基线完整、组件及 demo 与选择一致、无模板测试或组件文档残留，根文档链接有效。
- 核对单库裸 `*gorm.DB` / 双库包装、Kafka 完整包与单侧装配、HTTP 与 Swagger 配套、全部环境配置一致；检查初始化失败清理、退出清理、取消传播和关闭等待完整。
- 无外部依赖的 HTTP 组合使用临时端口验证实际路由与取消退出；外部组件只在明确提供的隔离环境验证。没有环境就报告连接与启动未验证，不以构建成功代替运行验证。
- 不新增测试文件，不把 go test 的“无测试文件”当作覆盖。按 [验收场景](references/trimming.md#验收场景)核对结果。
- 交付目标位置、应用名/module、保留基线与组件、demo、排除内容、实际验证和未验证项。失败时说明项目尚未完成，不自动删除生成结果或回滚用户文件。
