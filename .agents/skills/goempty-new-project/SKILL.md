# 从模板创建空服务

## 输入与定位

- 源模板是本技能文件所在 `.agents/skills/goempty-new-project/` 的项目根目录；根据实际加载的技能路径向上定位，不写死磁盘路径，不以当前工作目录替代源路径。检查根目录的 AGENTS.md、go.mod、README.md；无法定位时询问模板位置。
- 应用名是最低必要输入。目标默认是源模板父目录下的 `<应用名>`，例如源 `D:/project/goempty`、应用 `order-service` 对应 `D:/project/order-service`。用户显式指定路径时优先使用；相对路径按当前工作目录解析并报告绝对路径。
- Go module 默认等于应用名；指定完整模块地址时使用指定值。应用名必须是单个合法目录名且适合用作配置前缀，不接受路径分隔符、`.`、`..` 等路径值。不擅自把不合法名称改成另一个名称。
- MySQL、MongoDB、Redis、定时任务各自独立选择，数据库可以同时保留或均不保留。“只保留 MongoDB”只对这些可选组件取保留集合，HTTP 等基础能力仍保留；“去掉 MySQL”只移除指定组件。未说明时沿用模板现有组件。有冲突时先澄清。
- 默认移除 Hello 全链路示例、外部 Hello HTTP 客户端和生成项目内全部 `_test.go`；默认保留 Swagger 生成能力。明确的用户覆盖指令优先。

## 执行边界

先读取源模板及目标位置适用的 AGENTS.md，按其确认门禁执行。创建请求若已明确对应获确认方案，直接实施，不重复索要相同授权；新增范围或尚未确认的裁剪方案先列出具体清单再确认。源模板只读；删除全部测试的要求仅作用于生成项目。

创建前解析并核对源、目标绝对路径及已有父目录中的符号链接或 junction。目标不得等于源，也不得位于源目录内部。目标目录已存在时停止，不覆盖或自动合并。只在新建目标内修改和删除文件；递归删除前再次检查解析后的路径边界，不跟随链接到目标外部。未经单独授权，不执行 git init、add、commit 等改变 Git 状态的操作。

## 创建与裁剪

1. 检查工作区和源文件，只读取任务相关代码及文档；阅读 [裁剪规则](references/trimming.md)。以源当前实现为准，参考中的路径不是机械删除列表。源有未提交修改时说明采用当前磁盘内容，不覆盖或清理源。
2. 汇总应用名、目标绝对路径、module、组件选择、去示例和全部去测试策略，按适用门禁处理授权。缺少必需输入时询问；未指定 module 不阻塞。
3. 复制必要代码、文档和安全配置样例。排除 `.git`、本生成技能、其他仅供模板维护的工具配置、构建产物、日志、缓存、真实凭据和本机私有配置；检查隐藏文件，不按隐藏属性全部排除。保留有价值的 .gitignore、.editorconfig 和运行所需文件，不复制链接指向的源外内容。
4. 在目标内替换 go.mod module 和以原 module 为前缀的内部导入；更新应用默认名、配置文件名、API 元数据和文档身份。应用名与 module 分别处理，不对所有文本无差别替换，不擅自改数据库账号或连接真实服务。
5. 按引用关系同步裁剪代码、配置、组装、生命周期和文档。删除全部 `_test.go`，清理仅供测试使用的资源、依赖和说明；不删除仍有生产用途的代码。去示例后不创建空 Service、Repo、Job 或占位业务目录。
6. 在目标运行 README 规定的固定版本 Wire 生成命令，不手改 wire_gen.go；接口注释变化后重新生成 Swagger。依赖确实变化时运行 go mod tidy 并检查结果，不主动升级版本或新增生产依赖。下载或生成失败时保留真实错误，不能伪造生成产物。
7. 同步 README、AGENTS.md 导航、directory-structure.md、technology-stack.md、组件文档及所有环境 YAML，保留适用规范，删除已裁剪组件的专属说明与失效链接。不把源模板“保留基础测试”的要求留成新项目已有测试的承诺；保留后续正常开发的验证规范。

## 验证与交付

- 对目标修改的 Go 文件运行 gofmt，运行 `go vet ./...`、`go build ./...`。检查无 `_test.go`、原 module 导入、Hello 业务路由/任务或已移除组件的有效依赖；不以简单词匹配替代语义检查。
- 检查 Wire 的资源创建、初始化失败清理、退出清理与选择一致；Swagger 只包含实际保留接口，文档相对链接及锚点有效。
- 纯 HTTP 组合可用本机临时端口验证启动、healthz/readyz 和取消退出。外部组件只用明确提供的隔离环境；没有环境就报告未验证连接和启动，不以构建成功代替运行验证。
- 不为生成项目新增测试文件，不把 go test 的“无测试文件”当作测试覆盖。交付包含目标位置、应用名/module、组件清单、去测试及去示例结果、实际验证与未验证项。失败时明确项目尚未完成，不自动删除生成结果或回滚用户文件。
