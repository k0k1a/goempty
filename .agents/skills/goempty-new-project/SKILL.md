# 模板项目创建与组件同步

支持两种任务：按用户选择的组件集合创建新项目；向已有项目补充模板中缺失的组件及其示例、装配和根文档。

## 组件模型

- 不可裁剪的运行骨架：`cmd/app` 入口、`config` 加载与热加载、`pkg/log`、`pkg/env`、`internal/app` 的 Wire 与生命周期、根文档和 `go.mod`。
- 组件是裁剪单位：选中组件时，它的实现、示例实现（Hello 相关 demo）和根文档描述一起保留；示例不是独立选项，没有单独的示例开关。
- 其余全部可裁剪，包括 HTTP 入口、公共错误与响应、MySQL、PostgreSQL、MongoDB、Redis、Kafka 生产者与消费者、定时任务、异步任务池、事件总线、页码与游标分页、Swagger 生成和数据库迁移规范。
- 创建时必须至少选择一个运行入口：HTTP 入口、Kafka 消费者或定时任务；其余组件按依赖关系组合。
- 定时任务的示例通过事件总线发布问候事件，选择定时任务时连带保留事件总线和异步任务池。
- 组件清单、依赖关系、专属实现与连带调整见 [组件目录](references/trimming.md)；向已有项目同步的流程见 [同步规则](references/sync.md)。

## 输入与定位

- 源模板是本技能文件所在 `.agents/skills/goempty-new-project/` 的项目根目录；根据实际加载的技能路径向上定位，不写死磁盘路径，不以当前工作目录替代源路径。检查根目录的 AGENTS.md、go.mod、README.md；无法定位时询问模板位置。
- 应用名是最低必要输入。目标默认是源模板父目录下的 `<应用名>`，例如源 `D:/project/goempty`、应用 `order-service` 对应 `D:/project/order-service`。用户显式指定路径时优先使用；相对路径按当前工作目录解析并报告绝对路径。
- Go module 默认等于应用名；指定完整模块地址时使用指定值。应用名必须是单个合法目录名且适合用作配置前缀，不接受路径分隔符、`.`、`..` 等路径值。不擅自把不合法名称改成另一个名称。
- 组件集合是创建的必需输入，不提供默认值。用户未说明时，列出组件目录中的全部选项和依赖，请其选择；用户回答“全部”时按全部组件处理，回答“最小”时仅保留骨架和一个运行入口及其示例，并说明保留内容。
- 选中组件的示例实现、装配和根文档描述必须一并保留，不能只留组件实现。创建时默认删除生成项目内全部 `_test.go`，明确的用户覆盖指令优先。

## 执行边界

先读取源模板及目标位置适用的 AGENTS.md，按其确认门禁执行。创建或同步请求若已明确对应获确认方案，直接实施，不重复索要相同授权；新增范围或尚未确认的组件集合先列出具体清单再确认。源模板只读；删除全部测试的要求仅作用于新建项目。

创建前解析并核对源、目标绝对路径及已有父目录中的符号链接或 junction。目标不得等于源，也不得位于源目录内部。目标目录已存在时停止，不覆盖或自动合并。只在新建目标内修改和删除文件；递归删除前再次检查解析后的路径边界，不跟随链接到目标外部。未经单独授权，不执行 git init、add、commit 等改变 Git 状态的操作。

## 创建

1. 检查工作区和源文件，只读取任务相关代码及文档；阅读 [组件目录](references/trimming.md)。以源当前实现为准，参考中的路径不是机械删除列表。源有未提交修改时说明采用当前磁盘内容，不覆盖或清理源。
2. 汇总应用名、目标绝对路径、module、组件集合、Swagger 与迁移规范选择和测试清理策略，按适用门禁处理授权。组件集合缺失时先询问，不自行补齐。
3. 复制骨架和所选组件的代码、示例、文档与安全配置样例。排除 `.git`、本生成技能、其他仅供模板维护的工具配置、构建产物、日志、缓存、真实凭据和本机私有配置；检查隐藏文件，不按隐藏属性全部排除。保留有价值的 .gitignore、.editorconfig 和运行所需文件，不复制链接指向的源外内容。
4. 在目标内替换 go.mod module 和以原 module 为前缀的内部导入；更新应用默认名、配置文件名、API 元数据和文档身份。应用名与 module 分别处理，不对所有文本无差别替换，不擅自改数据库账号或连接真实服务。
5. 按引用关系同步裁剪代码、配置、组装、生命周期和文档。未选组件连同其配置字段、YAML 段、Wire 声明、App 参数、依赖和文档一起删除，不保留 nil、空切片或占位目录。`App.New`、`Run`、`Shutdown` 只接收所选运行组件，按组合裁剪参数、校验和等待逻辑。删除全部 `_test.go`，清理仅供测试使用的资源、依赖和说明；不删除仍有生产用途的代码。共享的 `HelloService` 按所选组件的实际引用裁剪字段、构造参数和方法，删除无引用部分；不保留空实现或占位业务目录。
6. 在目标项目中运行其 README 规定的 Wire 生成命令，不手改 wire_gen.go；接口注释变化后重新生成 Swagger。依赖确实变化时运行 go mod tidy 并检查结果，不主动升级版本或新增生产依赖。下载或生成失败时保留真实错误，不能伪造生成产物。
7. 同步 README、AGENTS.md 导航、architecture.md、conventions.md、组件文档及所有环境 YAML，只保留所选组件及其示例的说明，删除已裁剪组件的章节、目录树条目和失效链接。不把源模板“保留基础测试”的要求留成新项目已有测试的承诺，也不保留“示例能力按需保留”这类模板维护表述；保留后续正常开发的验证规范。

## 同步到已有项目

- 用户已有由本模板创建的项目，要求补充组件及其示例，或更新模板中的装配、根文档时执行同步；目标不是模板派生项目时先说明并确认。
- 同步只新增缺失组件及其示例，以及缺失的装配与根文档段落；示例随组件补充，不是独立范围。不覆盖目标已有业务实现，不删除目标文件，不新增任何 `_test.go` 或集成测试。
- 同步范围：组件专属实现及其示例、`internal/app` 装配与生命周期、组件对应的配置字段与 YAML 段，以及根文档（AGENTS.md、CLAUDE.md 入口、architecture.md、conventions.md、README.md）。不复制组件文档（`pkg/*/README.md`、`config/README.md`、`internal/*/README.md`）、生成技能、构建产物和日志。
- 目标已有同名路由、配置键、Service 方法或装配点时，先列出冲突和处理建议，不擅自覆盖。详细步骤见 [同步规则](references/sync.md)。

## 验证与交付

- 对目标修改的 Go 文件运行 gofmt，运行 `go vet ./...`、`go build ./...`。检查测试清理结果、模块导入和已移除组件的引用，包括配置段、`pkg` 包与 App 参数。按所选组件核对示例、路由、Wire 装配和 Swagger 条目，以及所选运行组件的启动与关闭。
- 检查 Wire 的资源创建、初始化失败清理、退出清理与选择一致；Swagger 只包含实际保留接口，文档相对链接及锚点有效。
- 纯 HTTP 组合可用本机临时端口验证启动、目标实际路由和取消退出；模板路径为 `GET /goempty/v1/healthz`、`GET /goempty/v1/readyz` 和 `GET /goempty/v1/hello`。无 HTTP 组合只验证所选运行组件。外部组件只用明确提供的隔离环境；没有环境就报告未验证连接和启动，不以构建成功代替运行验证。
- 新建项目不新增测试文件，不把 go test 的“无测试文件”当作测试覆盖；同步时保留目标现有测试，若装配签名变化导致其无法编译，做最小调整或说明冲突。交付包含目标位置、应用名/module、组件清单、各组件示例保留结果、测试处理结果、实际验证与未验证项。失败时明确项目尚未完成，不自动删除生成结果或回滚用户文件。
